What is the 8-Puzzle?

The 8-puzzle is a sliding-tile puzzle on a 3 × 3 grid holding the tiles 1 to 8 and one blank square. A move slides a neighbouring tile into the blank, which is the same as moving the blank up, down, left or right. The task is to turn a given initial state into a goal state using as few, or at least some, legal moves.

It is a classic example of a state-space search problem, and it is small enough to inspect completely, yet large enough that the choice of algorithm matters a great deal.

Formulation

  • State: an arrangement of the nine squares (tiles 1–8 and the blank).
  • Initial / goal state: chosen by the user, for example 2 8 3 / 1 6 4 / 7 _ 5 → 1 2 3 / 8 _ 4 / 7 6 5.
  • Actions: move the blank Up, Down, Left or Right when the move stays on the board.
  • Transition model: swap the blank with the neighbouring tile.
  • Path cost: 1 per move, so the path cost equals the number of moves.

What this application does

Flexible input

Type any initial and goal state, or generate a random puzzle that is guaranteed to be solvable.

Six algorithms

BFS, DFS, DLS, IDDLS, GBFS and A*, all written from scratch, plus UCS as a bonus.

Live search view

Current node, parent, depth, g/h/f, frontier, explored list and counters update on every step.

Measured results

Moves, nodes, time and approximate memory, plus a side-by-side comparison on one puzzle.

How to use it

  1. Open the Solver and set the initial and goal states, or press Generate Random Puzzle.
  2. Pick an algorithm. Set the depth limit for DLS, and the heuristic for GBFS or A*.
  3. Press Run. Use Pause, Resume, Next Step, Previous Step, the speed slider or the timeline to explore the search.
  4. Open Compare to run every algorithm on the same puzzle and read the table.

    Is a puzzle solvable?

    Exactly half of all arrangements can never reach a given goal. Sliding a tile horizontally never changes the inversion count of the tile sequence, and sliding it vertically changes it by an even number, so the parity of the number of inversions never changes.

    A puzzle is solvable exactly when the initial state and the goal state have the same inversion parity. This works for any goal, including the snail-shaped goal 1 2 3 / 8 _ 4 / 7 6 5 from the brief, where the common "inversions must be even" rule is not enough. The random generator in this app builds its puzzles by moving away from the goal, so they are always solvable.
